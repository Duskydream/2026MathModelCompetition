\section{演练测试与正式测试结果}\label{sec:results}

\subsection{测试环境与客户端}

机器狗程序用 Python 实现，通过 HTTP$+$JSON 与官方模拟器通信（默认 \url{http://127.0.0.1:2026}）。客户端遵守附件 2 的全部要求：以参赛队号作为 \texttt{robot\_id}，每个新动作使用新的 \texttt{request\_id}，\textbf{串行发送、逐次等待响应}，网络中断后重试时\emph{复用原请求内容与原 \texttt{request\_id}}；未知结果的动作标记为 \texttt{uncertain} 并禁止发出不同的后续动作，避免重复计时或状态错位。客户端按 \texttt{/enter} 返回的 \texttt{remaining\_real\_duration\_s} 设置现实截止时间，并在本地同步记录逐动作日志、配置哈希与定位证书，用于事后核对。

\subsection{成绩的正确解读}

三次正式测试是三个独立随机案例，样本量极小，因此必须说明成绩的口径：

\begin{enumerate}
  \item \textbf{三次成绩的差异主要由抽到的源数决定，而不是算法稳定性.} 由\cref{eq:fixedcost}，整局虚拟总时间的相对波动只有 $6\%$ 左右（第四问 $6329\pm395\msec$），但 $\bar T=T/n$ 在 $n=10$ 与 $n=16$ 之间可以相差近一倍。因此建议\textbf{同时报告整局虚拟总时间与平均定位清除时间}两个口径。
  \item \textbf{平均值的两种口径不能混用.} “各局 $T_i/n_i$ 再取算术平均”（案例均值）与“$\sum T_i/\sum n_i$”（合并均值）是不同的量，前者每局等权、后者按源数加权。本文所有对比都在同一口径下进行并在表注中标明。
  \item \textbf{清除比例是第一位的.} 只有在 $N_c=n$ 的前提下比较 $\bar T$ 才有意义；若某局未清完，$\bar T$ 反而可能因分母变小而“变好”，必须单列说明而不能混入平均。
  \item \textbf{程序运行时间不是算法效率指标.} 演练中程序运行时间为 $1.7\sim4.5\msec$，相对 $1200\msec$ 的限制有两到三个数量级的余量，主要由 HTTP 往返次数决定，与虚拟时间没有可比性。
\end{enumerate}
